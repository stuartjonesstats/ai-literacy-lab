# High-Interactivity Design

Not every module needs to be highly interactive. The project should push the envelope where interactivity creates better judgment, not where it creates novelty.

## Design Rule

Use high interactivity when the learner needs to experience a cognitive trap, tradeoff, uncertainty, or revision loop that passive reading cannot produce.

## Strong Candidates

### Module 2: Confidence Trap

Current direction:

- claim classification
- confidence rating
- local rewrite
- self-check rubric
- expert debrief

Future additions:

- side-by-side claim highlighting
- confidence rating before and after evidence review
- revision history showing how reasoning changed

### Module 3: Data Boundary Test

Potential interaction:

- learner redacts a realistic message
- learner chooses whether to paste, abstract, summarize, or avoid use
- hidden sensitivity markers reveal missed data risks
- self-check distinguishes direct identifiers, indirect identifiers, confidential business details, and safe abstractions

Current design:

- classify five synthetic customer messages by action
- identify risk signals in each message
- write a sanitized packet
- write a safer prompt
- compare against a local self-check and expert boundary review

Next escalation:

- add a time-pressure business-notes case
- ask learners to highlight phrase-level boundaries
- show a simulated AI summary that reintroduces sensitive details
- require a second-pass correction before the debrief
- end with an escalation fork

### Module 5: Human Review Challenge

Potential interaction:

- learner designs a review workflow
- simulation reveals time pressure, unclear ownership, missing evidence, and reviewer authority gaps
- learner must decide whether review is meaningful or ceremonial

### Module 7: Risk Escalation Fork

Potential interaction:

- branching scenario with changing context
- learner chooses proceed, modify, pause, document, or escalate
- risk meter updates based on consequence, reversibility, data sensitivity, affected people, and verification burden
- debrief compares several defensible paths rather than one correct answer

### Capstone: Workplace AI Decision Simulation

Potential interaction:

- multi-stage case file
- learner maintains a decision memo
- new information forces reclassification
- final recommendation is checked against a rubric
- optional export creates a local reflection artifact

## Productive Struggle Guardrails

High interactivity should still be pedagogically safe:

- make the task hard for the right reason
- reveal the misconception clearly
- give enough scaffolding to recover
- avoid gotchas based on obscure facts
- make debriefs respectful and actionable
- show that revision is learning, not failure

## Accuracy Guardrail

Highly interactive scenarios should prefer synthetic evidence packets. This makes the answers inspectable and reduces dependence on time-bound facts, legal interpretations, or vendor behavior.
